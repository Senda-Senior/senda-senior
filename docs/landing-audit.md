## ⚠️ ERRATA & QA — PASSADA POR CLAUDE (ORCHESTRATOR)

> **Data da revisão:** 2026-05-10
> **Por que existe:** Trae produziu o audit, Claude (orchestrator) fez QA antes de
> liberar o doc para consumo nas Phases 1, 2, 5. Esta seção lista TODOS os erros
> encontrados. As correções estão aplicadas inline nas seções abaixo.

### E1 — Seção 1: arrays inexistentes em Header.tsx
- Trae listou `NAV_COLUMNS` e `SOCIALS` em Header.tsx; ambos só existem em Footer.tsx
- Verificado por `grep -n '^const (NAV_COLUMNS|SOCIALS|NAV_LINKS)' src/features/landing/components/`
- **Correção:** linhas removidas da tabela. Total: 22 arrays (não 24).

### E2 — Seção 2: line numbers DESALINHADOS em todo o doc
- "L78 do Header.tsx" referenciado por Trae aponta na realidade para **L19** (declaração da constante `C = 'rgba(245, 240, 232, 1.00)'`)
- "L28-L30 do Footer.tsx" aponta para **L54-L56** (constantes INK/INK_MUTED/BG)
- Padrão: Trae erra os line numbers em ~50px de offset consistente
- **Correção:** Cursor (executor) NÃO deve usar line numbers para find/replace na Phase 2. Usar **string literal exata** (`'rgba(245, 240, 232, 0.80)'`) como search key.

### E3 — Seção 2: `--border-cream-25` mistura tipos
- Trae propõe `var(--border-cream-25) = '1.5px solid rgba(245,240,232,0.25)'` (border SHORTHAND inteiro como var)
- Anti-padrão: vars de cor devem armazenar **só cor**, não shorthand de border
- **Correção:** criar apenas `--color-cream-25: rgba(245,240,232,0.25)`; manter `'1.5px solid'` literal no inline style. (Phase 2 deve ignorar a sugestão do Trae aqui.)

### E4 — Seção 2: naming de opacidades é inconsistente
- Trae usa `--color-cream-80`, `--color-ink-08` (zero-padded), `--color-olive-30`. Sem padrão.
- **Correção (a ser decidida em Phase 2):** padronizar para zero-padded sem dash interno (`--color-ink-08`, `--color-cream-80`, `--color-olive-30`) **OU** migrar para padrão RGB-triplet + alpha composição (`rgb(var(--color-ink-rgb) / 0.08)`). Decisão fica para o usuário no início da Phase 2.

### E5 — Seção 3: `<SectionContainer />` proposto JÁ EXISTE (não criar)
- Trae propõe criar `<SectionContainer />` para o pattern 5 (max-width container com padding clamp)
- **`<Section>` já existe em `src/design/Section.tsx`** com tone (cream/creamMid/terracottaPale/green/dark/white/transparent), maxWidth (prose/content/wide/full) e padding `clamp(80px,10vw,140px)`
- **Correção:** ignorar sugestão de criar componente novo. Phases 4/5 usam `<Section>` existente. Pode-se estender com novos `tone` se necessário (ex: `'olive'` para `#595f43`).

### E6 — Seção 3: `<StarCluster />` proposto JÁ EXISTE (não criar)
- Trae propõe criar `<StarCluster />` para o pattern 8
- **`StarCluster` já existe e está exportado de `src/features/landing/shared/BrandStar.tsx:49`**
- Suporta props `size`, `mono`, `className`, `style`. Usa cores da paleta accent (terracotta, terracotta-light, gold, cream-dark) ou monocromático.
- **Correção:** ignorar sugestão. Phases 4/5 importam o StarCluster existente.

### E7 — Seção 3: `<Heading />` / `<Typography />` propostos VIOLAM o pattern budget
- Trae propõe criar `<Heading level="1|2|3" />` para padronizar tipografia (Pattern 6)
- **Plano explicitamente diz:** "Tipografia bespoke (clamp values únicos) FICA inline — não inventamos preset"
- Razão: cada seção tem hierarquia tipográfica única (clamp(36px,4.5vw,56px) para Hero; clamp(28px,3.6vw,48px) para Manifesto; etc). Forçar componente Heading vai introduzir variantes inflacionárias (size/level/tone/weight/letterSpacing props).
- **Correção:** ignorar sugestão. Phases 4/5 mantêm tipografia inline.

### E8 — Seção 3: Pattern 4 (`<GlassContainer />`) — avaliar caso-a-caso
- Trae propõe criar `<GlassContainer />` para o backdrop-blur pattern (8 ocorrências em 5 arquivos)
- **Status:** sugestão **válida potencialmente** — não há equivalente no design system, e é um pattern visualmente coerente
- **Decisão adiada:** avaliar se cabe na Phase 4 (pilot Servicos não usa esse pattern). Se cabe, criar como `<GlassPanel>` em `src/design/`. Se não, deixar inline pelos próximos sprints.

### E9 — WhatsAppFloat L13: dois valores no mesmo line ref
- Trae afirma `'rgba(255,255,255,0.9)'` E `'#25D366'` ambos em L13
- Provavelmente são linhas diferentes; Trae compactou
- **Correção:** Cursor verifica via grep no momento da Phase 2
